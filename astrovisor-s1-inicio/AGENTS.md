Trabajaremos en el proyecto AstroVisor utilizando OpenSpec como flujo interno de desarrollo.

Antes de realizar cualquier modificación:

1. Examina la estructura completa del repositorio y el código existente.
2. Identifica las funcionalidades implementadas, las incompletas y las que todavía no existen.
3. Consulta las especificaciones y cambios existentes de OpenSpec para evitar duplicar trabajo.
4. Utiliza el flujo de OpenSpec para preparar la propuesta, las especificaciones, el diseño técnico y las tareas correspondientes al cambio solicitado.
5. Preséntame el plan y espera mi aprobación antes de modificar código.

Una vez aprobado:

6. Implementa las tareas siguiendo las especificaciones.
7. Ejecuta las pruebas y verificaciones disponibles.
8. Documenta los resultados reales, los errores y las limitaciones.
9. Solicita mi aprobación antes de archivar el cambio.

Reglas del proyecto:

- AstroVisor está orientado principalmente a adultos mayores.
- La temática provisional es «Constelaciones e historias del cielo».
- Debe existir una experiencia web independiente del visor Homido.
- Se mantiene un panel administrativo simplificado.
- Los contenidos se manejarán preferentemente mediante archivos JSON/Markdown, sin base de datos relacional.
- No agregues funcionalidades fuera del alcance solicitado.
- Conserva y reutiliza el código existente siempre que sea viable.
- No reemplaces los diseños de interfaz que correspondan a otros integrantes.
- OpenSpec es una herramienta interna; sus archivos y procesos no forman parte de los entregables académicos del sprint.

Distingue siempre entre funcionalidades implementadas, simulaciones y trabajo pendiente.
